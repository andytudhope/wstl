# Status Lovers (Still)

A small [OpenZeppelin ERC721](https://docs.openzeppelin.com/contracts/5.x/erc721) wrapper for [an old NFT contract that coined the term 'digibles' for digital collectibles](https://etherscan.io/address/0x5bb0a11b5ddc8e83c21c09fd34caf49a18e91232).

**Live on Ethereum mainnet:** [`0x181a52b6E9cb690Aa7E0C9469175d908d64800dD`](https://etherscan.io/address/0x181a52b6E9cb690Aa7E0C9469175d908d64800dD#code).

- Only original token IDs **0–49** can be wrapped, once each, after being deposited.
- Originals stay in the wrapper **permanently**. No unwrap, admin, upgrade, or extra mint function.
- Wrapped receipts can be transferred and approved for marketplace trading normally.

## Minimal escrow sale

1. A buyer sends ETH directly to the wrapper address with empty calldata. Anyone can deposit any amount, and top-ups accumulate in `deposits(buyer)`.
2. The buyer calls `withdraw()` to recover their full unused deposit.
3. The deployer calls `bulkSale(buyer, expectedDeposit)` to exchange **all 50 wrapped tokens** for that buyer's entire deposit, in one transaction. `expectedDeposit` is the exact amount in **wei**.

These methods can be used through the verified contract on Etherscan. 

The expected-amount check prevents a withdrawal or changed deposit from silently reducing the sale price before the seller's transaction is mined. The deposit is cleared before any receiver callback, and NFT delivery and ETH payment are atomic. A failed NFT transfer or ETH payment reverts the whole sale, leaving the deposit withdrawable. Money-moving methods use [OpenZeppelin's reentrancy guard](https://docs.openzeppelin.com/contracts/5.x/api/utils#ReentrancyGuardTransient).
Other depositors' ETH is unaffected and remains withdrawable.

## Metadata

At Ethereum block **26,253,872**, the original contract had 50 tokens, IDs 0–49, all owned by the `thebluebook.eth`. 

Every `tokens(id)` value was `0x491cefc086eba40f46f5ad79b60c1a550b09875a200378fa7225553829cec902`.

Adding the SHA-256 multihash prefix `0x1220` and base58 encoding gives exactly the original CID: `QmTG44cVAw4k58BNnb2AZ5PMeFYwRjcZ7qwhhNYzBrsKjP`.

`tokenMetadata(0)` on the original contract returns `"Digibles"`.

The wrapped collection is named **Status Lovers (Still)** in both `name()` and `contractURI()`.

Its symbol is `wSTL`; individual token names remain `Status Lovers #0` through `Status Lovers #49`.

The wrapper returns immutable onchain JSON with the token name, original contract,
original ID, original IPFS URI, and an embedded SVG image. It includes the following [marketplace attributes](https://docs.opensea.io/docs/media-and-traits):

- Original mint date, block, and token ID.
- Edition `Original 50` and wrapped edition size `50`.
- Permanent custody of the matching original.
- Actual rescue date and block.
- Original media status at rescue: `Not recovered`.
- Artwork year `2026`, medium `Onchain generative SVG`, and the three named palette colours.

A separate `provenance` object records the original deployment and mint transactions, blocks, timestamps, original minting wallet, and Ethereum chain ID. 

The `artwork` object credits the Status heart and links to the brand kit. The token's `external_url` points to the original mint transaction. The rescue story uses these verified facts.

`rescues(id)` records that token's `block.number` and `block.timestamp` when `wrap()` successfully mints its receipt. Tokens wrapped together share a date and block; tokens wrapped later get their own records.

Each record uses one packed storage slot and cannot be overwritten by another wrap or transfer. Both the record and the token metadata stay fixed after minting. There is no metadata setter.

## Artwork

Each token has a centred white heart taken from the official [Status brand kit](https://status.app/brand). The renderer uses only its main and custom colours as gradient and blur inputs. A hash of `("Status Lovers", tokenId)` determines three distinct colours, the gradient direction, and the position, size, and blur of the background colour fields. The heart path is the original vector, unchanged.

The artwork is generated by `src/StatusLoversArt.sol` and embedded directly into `tokenURI`. It stays identical across owners, wallets, and chains. It needs no IPFS gateway, image server, fonts, or scripts. Each SVG is 3000 × 3000 and scales as a vector. The original CID remains an independent provenance reference..
